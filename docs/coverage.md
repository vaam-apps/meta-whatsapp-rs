# Feature coverage

What `meta-whatsapp-rs` covers of Meta's WhatsApp Business Platform, in priority order.
Doc paths are relative to
`https://developers.facebook.com/documentation/business-messaging/whatsapp/`.

This is the per-feature list. [parity.md](parity.md) compares the same
code with Zaileys and Meta's Cloud API, capability by capability, and
[categories.md](categories.md) sums it up by Meta platform category (each
of its rows links back to the rows here); [roadmap.md](roadmap.md) plans
what is missing. A PR that changes a feature updates its row here and in
those tables.

Status: **done** = implemented and tested against the docs' request/response
examples (each area went through an implementation pass and an adversarial
review with mutation testing); **partial** = the listed subset only;
**planned** = not yet; **out of scope** = deliberately not covered, with the
reason. Verified against the docs as mirrored on 2026-09-24 (Graph API
v25.0).

Grading follows the rule stated once in
[parity.md § How to read the table](parity.md#how-to-read-the-table) (so a
row with a documented endpoint or field not wrapped is partial, naming
it); this file's **planned** is parity.md's gap, and its **out of scope**
parity.md's n/a.
